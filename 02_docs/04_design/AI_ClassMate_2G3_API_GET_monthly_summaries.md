# API Design — GET /api/monthly-summaries

## Purpose
List summary rows for a class/month.

## Query
- `classId` required
- `period` required (`YYYY-MM`)
- optional `calculationStatus`, `page`, `pageSize`

## Success — 200
Returns one row per student for the selected class/month, including pseudonymous student code, positive points, negative points, total, gift count, remainder (nullable), data/calculation status and approval status.

## Behavior
- Do not compute values in the controller; query the stored summary generated by domain services.
- If no calculation has run, return an empty collection or documented `404` state consistently. Recommended: `200` with empty collection and `meta.total=0`.
- Never hide `NEEDS_REVIEW` rows from the default result.

## Errors
`400 VALIDATION_ERROR`, `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 CLASS_NOT_FOUND`.

## Acceptance tests
- One row per active or otherwise in-scope student according to the documented monthly roster policy.
- Null remainder is preserved for negative totals.
- Review-needed rows remain visible.
